# دليل أنواع العمليات التشغيلية (YouTrack Operation Types Guide)

**الملف المصدري البرمجي:** [`internal/services/permissions_services/permission.go`](../../internal/services/permissions_services/permission.go#L51-L63)  
**سجل الصلاحيات ومصفوفة التطبيق:** [`internal/services/permissions_services/catalog.go`](../../internal/services/permissions_services/catalog.go)  
**النطاق المعماري:** محرك الصلاحيات ونموذج حوكمة الموارد (Access Control & Operations)

## 1. ما هو نوع العملية (`OperationType`) في نظام الصلاحيات؟

في هندسة البرمجيات وأنظمة إدارة الوصول المعقدة مثل **JetBrains YouTrack**، لا يكفي تعريف الصلاحية بمجرد اسم نصي مبهم (مثل `PERM_01`) أو الاكتفاء بالنموذج الرباعي التقليدي البسيط (CRUD).

يمثل `OperationType` **الفعل التشغيلي أو الغرض الإجرائي** الذي ينفذه المستخدم أو النظام ضد كيان معين (`EntityType`) ضمن نطاق صلاحيات محدد (`ScopeLevel`).

```go
// OperationType defines the CRUD or operational action.
type OperationType string

const (
    OpCreate  OperationType = "CREATE"
    OpRead    OperationType = "READ"
    OpUpdate  OperationType = "UPDATE"
    OpDelete  OperationType = "DELETE"
    OpLink    OperationType = "LINK"
    OpShare   OperationType = "SHARE"
    OpAdmin   OperationType = "ADMIN"
    OpSpecial OperationType = "SPECIAL"
)
```

### الأهمية المعمارية لوجود هذا التصنيف

1. **تجاوز حدود CRUD التقليدية:**  
   العمليات في بيئات تتبع المشاريع لا تنحصر في إنشاء أو قراءة أو تعديل سجل بقاعدة البيانات؛ بل تتضمن أفعالاً ذات طبيعة شبكية (مثل ربط التذاكر ببعضها `OpLink`)، أو حركية تعاونية وتفويض للرؤية (مثل مشاركة اللوحات والوسوم `OpShare`)، أو استثناءات تشغيلية خاصة (مثل تنفيذ الأوامر بصمت `OpSpecial`).
2. **بناء مصفوفة الصلاحيات (Orthogonal Matrix):**  
   عند دمج الكيان (`EntityType`) مع نوع العملية (`OperationType`)، تتكون مصفوفة متكاملة تتيح الاستعلام البرمجي الفعال:  
   *(هل يملك هذا الدور صلاحية من نوع `UPDATE` على الكيان `COMMENT`؟)*.
3. **تطبيق مبدأ الامتيازات الأقل (Principle of Least Privilege):**  
   فصل العمليات يتيح منح المستخدم صلاحية الربط `OpLink` أو المشاركة `OpShare` دون منحه حق التعديل الجوهري `OpUpdate` على حقول التذكرة أو المشروع.
4. **حوكمة العمليات الحساسة وإجراءات الطوارئ:**  
   عزل العمليات الإدارية المنخفضة `OpAdmin` والعمليات الخاصة `OpSpecial` يمنع منح صلاحيات خطرة عن طريق الخطأ لمستخدمي المشاريع العاديين.

## 2. جدول المقارنة الشامل للعمليات التشغيلية الثماني

| # | نوع العملية البرمجي | القيمة النصية | الدلالة الإجرائية | مستوى الأثر والخطورة | أمثلة حية من YouTrack |
| :-: | :--- | :--- | :--- | :---: | :--- |
| **1** | `OpCreate` | `"CREATE"` | إنشاء وإضافة كيانات جديدة إلى النظام | متوسط | إنشاء تذكرة، كتابة مقال، رفع مرفق، تسجيل وقت |
| **2** | `OpRead` | `"READ"` | استعراض وقراءة البيانات والتقارير | منخفض إلى حساس | قراءة التذاكر العامة، قراءة الحقول السرية، قراءة الملفات الشخصية |
| **3** | `OpUpdate` | `"UPDATE"` | تعديل المحتوى، وتحديث البيانات، وتغيير الحالات | متوسط إلى مرتفع | تعديل نص تذكرة، تعديل تعليق، تعديل الملف الشخصي، ترقية مشروع |
| **4** | `OpDelete` | `"DELETE"` | حذف وإزالة الموارد نهائياً أو أرشفتها | عالي جداً (تدميري) | حذف تذكرة، حذف مشروع، حذف حساب مستخدم، حذف تعليق |
| **5** | `OpLink` | `"LINK"` | بناء وإدارة شبكة العلاقات والاعتماديات بين الكيانات | متوسط | ربط تذكرة بتذكرة أخرى (تبعية، تكرار، مهمة فرعية) |
| **6** | `OpShare` | `"SHARE"` | تفويض الوصول ومشاركة الكيانات المخصصة مع الآخرين | متوسط إلى حساس | مشاركة الوسوم (Tags)، استعلامات البحث المحفوظ، اللوحات المرنة |
| **7** | `OpAdmin` | `"ADMIN"` | التحكم العميق في البنية التحتية والخادم والمحرك | أقصى درجات الخطورة | تعديل إعدادات السيرفر، إدارة النسخ الاحتياطي، ترقية النظام |
| **8** | `OpSpecial` | `"SPECIAL"` | إجراءات تجاوز الخصوصية أو التنفيذ الاستثنائي المشروط | حساس جداً | تنفيذ الأوامر بصمت، تجاوز حجب الحقول والرؤية المقيدة |

## 3. شرح تفصيلي ومعمق لكل عملية تشغيلية

### 1. عملية الإنشاء (`OpCreate = "CREATE"`)

- **المفهوم التشغيلي:**  
  تمثل إذن المبادرة بإنشاء مورد جديد داخل النظام. عند نجاح هذه العملية، يتم توليد معرّف فريد للكيان، وتعيين منشئ المورد كـ "مالك أول" (Owner/Author)، مما يفعل لاحقاً حقوق الملكية الذاتية (Inherent Rights).
- **التدرج الدقيق في YouTrack:**  
  لا تقتصر على الإنشاء البسيط، بل تراعي سياق الملكية:
  - `CREATE_WORK_ITEM`: تسجيل ساعات عمل للمستخدم نفسه.
  - `CREATE_NOT_OWN_WORK_ITEM`: تسجيل ساعات عمل نيابة عن عضو آخر في الفريق (صلاحية إشرافية).
- **أمثلة برمجية من الكتالوج:**
  - `PermCreateIssue`: إنشاء تذكرة عمل جديدة في المشروع.
  - `PermCreateArticle`: نشر مقال جديد في قاعدة المعرفة.
  - `PermAddAttachment`: رفع مرفق جديد إلى تذكرة قائمة.
  - `PermCreateProject`: إنشاء مشروع جديد كلياً في الخادم.

---

### 2. عملية القراءة والاستعراض (`OpRead = "READ"`)

- **المفهوم التشغيلي:**  
  استرجاع البيانات من قاعدة البيانات وعرضها في واجهة المستخدم أو إرسالها عبر واجهات برمجة التطبيقات (REST APIs). القراءة هي العملية الأكثر شيوعاً، ولكنها تتضمن درجات أمان متفاوتة وفق حساسية المورد.
- **التدرج الدقيق في YouTrack:**  
  تتميز YouTrack بفصل دقيق لمستويات القراءة لمنع تسرب البيانات:
  - **قراءة أساسية مقابل تفصيلية (Basic vs Details):**  
    `PermReadUserBasic` تتيح فقط رؤية اسم المستخدم وصورته لإسناد المهام، بينما `PermReadUserDetails` تتيح استعراض البريد الإلكتروني وسجلات الدخول والمجموعات.
  - **قراءة عامة مقابل قراءة حقول خاصة (Public vs Private):**  
    `PermReadIssue` تتيح قراءة الحقول العامة للتذكرة، في حين أن `PermReadIssuePrivateFields` (`PRIVATE_READ_ISSUE`) مطلوبة لقراءة الحقول الحساسة (مثل تكاليف التطوير، تقييمات الأداء).
  - **استعراض التفاعل الاجتماعي:**  
    `PermViewWatchers` و `PermViewVoters` تتيحان معرفة من يتابع التذكرة أو يصوت لصالحها دون فتح صلاحيات التعديل.

---

### 3. عملية التحديث والتعديل (`OpUpdate = "UPDATE"`)

- **المفهوم التشغيلي:**  
  تعديل كائن موجود بالفعل. تشمل هذه العملية تعديل النصوص، وتغيير حالات دورة العمل (Workflow States)، وتغيير المسؤولين (Assignees)، وتحديث الإعدادات.
- **التدرج الدقيق في YouTrack:**  
  - **تعديل موارد الذات مقابل موارد الآخرين:**  
    `PermUpdateSelf` تتيح للمستخدم تعديل إعدادات أمان حسابه الشخصي فقط، بينما `PermUpdateUser` تتيح للمسؤول حظر الحسابات أو دمجها أو تغيير بيانات موظفين آخرين.
  - **التعديل الميداني للتعليقات وتتبع الوقت:**  
    `PermUpdateIssueComment` تتيح للمستخدم تعديل تعليقه هو، بينما `PermUpdateNotOwnIssueComment` تمنح قائد الفريق حق تعديل أو تصحيح تعليقات زملائه.
- **أمثلة برمجية من الكتالوج:**
  - `PermUpdateIssue`: تعديل حقول التذكرة القياسية.
  - `PermUpdateIssuePrivateFields`: تعديل الحقول السرية للمشروع.
  - `PermUpdateWatchers`: إضافة أو إزالة زملاء من قائمة المتابعين للتذكرة.

---

### 4. عملية الحذف والإلغاء (`OpDelete = "DELETE"`)

- **المفهوم التشغيلي:**  
  تدمير أو إلغاء وجود الكيان في النظام. نظراً لخطورة هذه العملية وتأثيرها على استمرارية البيانات وسجلات التدقيق (Audit Logs)، تُعزل في YouTrack بحذر شديد وغالباً ما تكون غير مفعلة للمستخدمين العاديين.
- **التدرج الدقيق في YouTrack:**  
  - **الحذف الذاتي المشروط:** السماح بحذف التعليق أو المرفق الشخصي خلال فترة زمنية محددة.
  - **الحذف الإداري الدائم:** `PermDeleteNotOwnAndPermanentCommentDelete` تمكّن المشرفين من إزالة تعليقات الآخرين وحذفها نهائياً من السجلات في حال احتوت على بيانات سرية أو غير لائقة.
  - **حذف الكيانات الكبرى:** `PermDeleteProject` و `PermDeleteOrganization` تمس مساحات عمل كاملة وتشمل حذف جميع التذاكر والمرفقات التابعة لها دفعة واحدة.

---

### 5. عملية الربط الطوبولوجي (`OpLink = "LINK"`)

- **المفهوم التشغيلي:**  
  إنشاء أو فك الروابط والعلاقات الشبكية بين كيانين مستقلين دون تعديل المحتوى الداخلي لأي منهما.
- **لماذا فُصلت كنوع عملية مستقل بدلاً من دمجها في `UPDATE`؟**
  1. **التعامل مع طرفين (Two-ended Entity Interaction):** عند ربط التذكرة A بالتذكرة B (مثلاً علاقة `Depends on` أو `Duplicates`)، فإن العملية تؤثر على تذكرتين في آن واحد، وقد تكون التذكرة الثانية في مشروع آخر يملك فيه المستخدم صلاحيات مختلفة.
  2. **حقوق الربط التلقائية (Inherent Link Rights):** في YouTrack، إذا كنت أنت من أنشأ التذكرة، يمنحك النظام حق ربطها تلقائياً (`InherentLinkOwnIssue`) حتى لو لم تكن تملك صلاحية `PermUpdateIssue` الشاملة على التذكرة.
- **الصلاحية المرتبطة في الكتالوج:**
  - `PermLinkIssue` (`LINK_ISSUE`): ربط تذاكر العمل ببعضها في المشاريع.

---

### 6. عملية المشاركة وتفويض الرؤية (`OpShare = "SHARE"`)

- **المفهوم التشغيلي:**  
  تغيير نطاق إتاحة كائن شخصي (Private Resource) ليصبح متاحاً للاستخدام أو الرؤية من قبل مجموعات أو فرق عمل أخرى (Shared Resource).
- **لماذا تُعد عملية قائمة بذاتها؟**
  - المورد (مثل وسم معين أو استعلام بحث مخصص) يظل محتواه كما هو دون تعديل، لكن **قائمة التحكم بالوصول الخاصة به (ACL - Access Control List)** هي التي تتغير.
  - منع الإزعاج وسوء الاستخدام (Spam Prevention): إذا سُمح لأي مستخدم بمشاركة وسومه وعمليات بحثه علناً مع الجميع، ستمتلئ القوائم المشتركة بمئات الوسوم الشخصية العشوائية. لذلك تقتصر هذه العملية على أدوار محددة.
- **الصلاحية المرتبطة في الكتالوج:**
  - `PermShareWatchFolder` (`SHARE_WATCH_FOLDER`): مشاركة الوسوم وعمليات البحث المحفوظة ولوحات المتابعة مع أعضاء المشروع أو المجموعات.

---

### 7. عملية الإدارة منخفضة المستوى (`OpAdmin = "ADMIN"`)

- **المفهوم التشغيلي:**  
  التحكم الإداري المباشر في المحرك والخادم والبيئة التحتية التي يعمل عليها التطبيق.
- **الفرق بين `OpAdmin` و `OpUpdate`:**
  - `OpUpdate`: تعديل بيانات الأعمال (مثل تعديل اسم مشروع، أو تحديث دور موظف، أو تغيير وصف تذكرة).
  - `OpAdmin`: تعديل تكوين النظام التقني (مثل تغيير منافذ الاتصال، إعدادات خادم البريد SMTP، ضبط ذاكرة JVM، جدولة النسخ الاحتياطي لقاعدة البيانات، أو تهيئة موفري الهوية ومفاتيح SAML/OAuth).
- **مستوى الحرج:**  
  أي إجراء تحت هذه العملية ينطوي على مخاطر تعطل الخدمة أو انهيار الخادم بالكامل، لذا يُخصص لها نطاق عام فقط (`ScopeGlobal`) وتُحجب تماماً عن مديري المشاريع.
- **الصلاحية المرتبطة في الكتالوج:**
  - `PermLowLevelAdminWrite` (`ADMIN_UPDATE_APP`): التعديل الإداري المباشر لإعدادات الخادم والمنصة.

---

### 8. العمليات الاستثنائية والخاصة (`OpSpecial = "SPECIAL"`)

- **المفهوم التشغيلي:**  
  إجراءات حوكمة وسلوكيات تشغيلية ظرفية تتجاوز القواعد المعتادة للتدفق الطبيعي للبيانات، ولا يمكن نمذجتها كعمليات CRUD بسيطة.
- **حالات الاستخدام الرئيسية في YouTrack:**
  1. **التنفيذ الصامت (`PermApplyCommandsSilently` / `APPLY_COMMANDS_SILENTLY`):**  
     تطبيق أوامر جماعية وتغييرات واسعة على التذاكر دون إرسال رسائل بريد إلكتروني أو إشعارات مزعجة للفرق. تُستخدم عند هجرة البيانات، أو إعادة التنظيم الإداري الدوري.
  2. **تجاوز قيود الظهور وحجب المحتوى (`PermOverrideVisibility` / `READ_HIDDEN_STUFF`):**  
     تخطي قيود الرؤية الجماعية التي يضعها المستخدمون على تذاكرهم أو تعليقاتهم؛ وهي صلاحية رقابية استثنائية مخصصة لمديري الأمن والامتثال القانوني لفحص المحتوى المحجوب دون الحاجة لإضافتهم يدوياً في كل مجموعة خصوصية.

## 4. كيف تتكامل العمليات (`OperationType`) مع بنية الصلاحية (`Permission`)؟

داخل الكود المصدري في [`permission.go`](../../internal/services/permissions_services/permission.go#L48-L60)، تتكامل ثلاثة أبعاد لبناء كل صلاحية وفق معيار YouTrack الرسمي:

```text
 ┌───────────────────────────────────────────────────┐
 │                YouTrack Permission                │
 ├──────────────────┬──────────────┬─────────────────┤
 │    EntityType    │  ScopeLevel  │  OperationType  │
 │ (المورد المستهدف)│ (نطاق الأثر) │ (الفعل المنفذ)  │
 └──────────────────┴──────────────┴─────────────────┘
```

### أمثلة من الكتالوج البرمجي تُوضح هذا التناغم

```go
// catalog examples
// 1. صلاحية إنشاء مقال في قاعدة المعرفة:
Permission{
    ID:        "CREATE_ARTICLE",
    Entity:    EntityArticle,    // الكيان: المقال
    Scope:     ScopeProject,     // النطاق: داخل المشروع
    Operation: OpCreate,         // العملية: إنشاء
}

// 2. صلاحية ربط التذاكر ببعضها:
Permission{
    ID:        "LINK_ISSUE",
    Entity:    EntityIssue,      // الكيان: التذكرة
    Scope:     ScopeProject,     // النطاق: داخل المشروع
    Operation: OpLink,           // العملية: ربط طوبولوجي
}

// 3. صلاحية تخطي مجموعات الرؤية الخاصة (تدقيق ورقابة):
Permission{
    ID:        "READ_HIDDEN_STUFF",
    Entity:    EntityIssue,      // الكيان: التذكرة
    Scope:     ScopeProject,     // النطاق: داخل المشروع
    Operation: OpSpecial,        // العملية: تدقيق وتجاوز استثنائي
}

// 4. صلاحية مشاركة مجلدات البحث والوسوم:
Permission{
    ID:        "SHARE_WATCH_FOLDER",
    Entity:    EntityWatchFolder, // الكيان: مجلد المتابعة
    Scope:     ScopeProject,      // النطاق: داخل المشروع
    Operation: OpShare,           // العملية: تفويض ومشاركة
}
```

## 6. الخلاصة والقيمة الهندسية

إن اعتماد `OperationType` كنوع مخصص ذو قيم واضحة:

- يمنح المحرك البرمجي **أماناً نوعياً (Type Safety)** في لغة Go ويمنع كتابة نصوص عشوائية في تعريف الصلاحيات.
- يتيح لكتاب قواعد التحقق والـ Evaluators فحص نوع الفعل مباشرة:  
  `if perm.Operation == perms.OpDelete && !user.IsAdmin() { ... }`.
- يعكس التمايز الواقعي بين عمليات الموارد العادية (CRUD) والعمليات المتقدمة للأدوات التعاونية الحقيقية مثل JetBrains YouTrack.
