# المستويات التنظيمية في نظام صلاحيات YouTrack

# (Organizational Levels in YouTrack Permission System)

**نوع المستند:** بحث مرجعي من المصادر الرسمية  
**المصدر الرئيسي:** JetBrains YouTrack Official Documentation  
**تاريخ البحث:** 2026-10-05  
**الموضوع:** المستويات التنظيمية (Organizational Levels) — ليس النطاقات (Scopes)

---

## تمهيد: لماذا التمييز بين "المستويات التنظيمية" و"النطاقات"؟

في توثيق YouTrack الرسمي، كثيراً ما يتم الخلط بين مفهومين مترابطين لكنهما مختلفان جوهرياً:

| المفهوم | التعريف | الدور في النظام |
| --------- | --------- | ---------------- |
| **النطاق (Scope)** | البُعد الأمني الذي يحدد **أين تسري** الصلاحية (Global / Organization / Project) | يُستخدم لتفعيل أو تعطيل الصلاحيات عند إسناد الدور |
| **المستوى التنظيمي (Organizational Level)** | الكيان الإداري الهرمي الذي يُدار عنده الوصول فعلياً (المستخدم، المجموعة، الفريق، المشروع، المؤسسة، النظام) | يُستخدم لتحديد **مَن** يملك الدور و**أين** يُسند، وكيف يتوارث |

> **الخلاصة:** النطاق هو **خاصية على الصلاحية ذاتها**، بينما المستوى التنظيمي هو **الهيكل الإداري** الذي يتم فيه **إسناد الأدوار وتوزيعها**.

---

## 1. المستويات التنظيمية الستة في YouTrack

بناءً على التوثيق الرسمي لـ JetBrains، يعمل نظام الصلاحيات عبر ستة مستويات تنظيمية مترابطة هرمياً:

```text
┌─────────────────────────────────────────────────────────┐
│                  System (النظام الكامل)                   │
│  ┌───────────────────────────────────────────────────┐   │
│  │          Organization (المؤسسة)                    │   │
│  │  ┌─────────────────────────────────────────────┐   │   │
│  │  │         Project (المشروع)                    │   │   │
│  │  │  ┌───────────────────────────────────────┐   │   │   │
│  │  │  │    Team / Group (الفريق/المجموعة)      │   │   │   │
│  │  │  │  ┌─────────────────────────────────┐   │   │   │   │
│  │  │  │  │      User (المستخدم الفرد)       │   │   │   │   │
│  │  │  │  └─────────────────────────────────┘   │   │   │   │
│  │  │  └───────────────────────────────────────┘   │   │   │
│  │  └─────────────────────────────────────────────┘   │   │
│  └───────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────┘
```

### 1.1 مستوى النظام (System Level)

**الوصف الرسمي:** المستوى الأعلى الذي يشمل كامل مثيل YouTrack.

- **مَن يعمل على هذا المستوى:** مدير النظام (System Admin).
- **آلية إسناد الأدوار:** يتم من خلال `Administration > Access Management > Roles`.
- **أمثلة على العمليات:**
  - إنشاء مستخدمين جدد (Create User)
  - إنشاء مشاريع جديدة (Create Project)
  - إدارة المجموعات على مستوى النظام (Create/Delete Group)
  - إدارة إعدادات الخادم والنسخ الاحتياطي
- **القاعدة الرسمية:** الأدوار المُسندة على مستوى النظام تُفعِّل **جميع** الصلاحيات بكل نطاقاتها (Global + Organization + Project).
- **الدور الافتراضي:** `System Admin` — يملك كل الصلاحيات عبر كل النطاقات.

### 1.2 مستوى المؤسسة (Organization Level)

**الوصف الرسمي:** حاوية تنظيمية (Container) تجمع مشاريع متعددة تحت مظلة واحدة.

- **الغرض:** تبسيط إدارة الوصول عبر مشاريع متعددة دفعة واحدة بدلاً من إسنادها مشروعاً بمشروع.
- **آلية الوصول:** `Administration > Access Management > Organizations`.
- **آلية إسناد الأدوار:** من خلال تبويب **Access** في إعدادات المؤسسة.
- **القاعدة الرسمية:** عند إسناد دور على مستوى المؤسسة، تُمنح الصلاحيات **لجميع المشاريع** المنتمية لتلك المؤسسة تلقائياً.
- **السلوك المهم:**
  - إذا احتوى الدور على صلاحيات **عامة (Global)** وأُسند على مستوى المؤسسة → تُتجاهل الصلاحيات العامة، وتُفعَّل فقط صلاحيات المؤسسة والمشروع.
  - YouTrack يمنع إسناد دور لا يحتوي على صلاحية واحدة على الأقل متوافقة مع نطاق المؤسسة.

### 1.3 مستوى المشروع (Project Level)

**الوصف الرسمي:** المستوى الأكثر تحديداً في الهرم التنظيمي، يخص مشروعاً واحداً بعينه.

- **آلية إسناد الأدوار:** من خلال `Project Settings > People`.
- **العمليات النموذجية:**
  - عرض التذاكر (Read Issue)
  - إنشاء التذاكر (Create Issue)
  - تعديل التعليقات (Update Comment)
  - إدارة إعدادات المشروع (Project Admin فقط)
- **القاعدة الرسمية:** يمكن للمستخدم نفسه أن يحمل أدواراً مختلفة في مشاريع مختلفة — مثلاً `Contributor` في المشروع أ و`Observer` في المشروع ب.
- **السلوك المهم:**
  - إذا أُسند دور يحتوي صلاحيات عامة وصلاحيات مشروع على مستوى المشروع → تُفعَّل فقط **صلاحيات المشروع** وتُتجاهل الصلاحيات العامة.

### 1.4 مستوى المجموعة (Group Level)

**الوصف الرسمي:** المجموعات هي تجمعات من حسابات المستخدمين تُستخدم لتوحيد إدارة الوصول.

- **الفرق بين المجموعة والفريق:**

| الخاصية | المجموعة (Group) | فريق المشروع (Project Team) |
| --------- | ------------------ | --------------------------- |
| **النطاق** | عابرة للمشاريع — يمكن استخدامها في عدة مشاريع ومؤسسات | مرتبطة بمشروع واحد فقط |
| **الاستخدام الأمثل** | إدارة وصول موحد لمجموعة مستخدمين عبر مشاريع متعددة | إدارة وصول خاص بمشروع محدد |
| **التحديث** | تحديث عضوية المجموعة يُحدّث الوصول تلقائياً في كل مكان تُستخدم فيه | التحديث يؤثر على المشروع المرتبط فقط |

- **آلية إسناد الأدوار:** يتم إسناد الأدوار للمجموعة، وكل أعضاء المجموعة يرثون تلك الأدوار.
- **القاعدة الرسمية:** المجموعات هي الآلية المُفضلة (Recommended) لإدارة الوصول على نطاق واسع بدلاً من الإسناد الفردي.

### 1.5 مستوى فريق المشروع (Project Team Level)

**الوصف الرسمي:** كل مشروع في YouTrack يملك فريقاً خاصاً به.

- **آلية العمل:** عند إضافة مستخدم أو مجموعة لفريق المشروع، يحصل تلقائياً على الأدوار المُسندة لذلك الفريق.
- **الفائدة:** تبسيط الإسناد — بدلاً من إسناد أدوار فردية لكل مستخدم جديد، يكفي إضافته للفريق.
- **ملاحظة رسمية:** الفريق يعمل كـ"طبقة وسيطة" بين المجموعة والمشروع.

### 1.6 مستوى المستخدم الفرد (Individual User Level)

**الوصف الرسمي:** يمكن إسناد الأدوار مباشرة لمستخدم فرد.

- **آلية الإسناد المباشر:** من خلال `Administration > Users > [اسم المستخدم] > Roles Tab > Assign Role`.
- **آلية الإسناد عبر المشروع:** من خلال `Project Settings > People > Add Member`.
- **عرض ملخص الصلاحيات:** تبويب **Roles** في صفحة حساب المستخدم يعرض كل الأدوار المُسندة، مصنفة حسب:
  - **Direct** — أدوار مُسندة مباشرة
  - **Team** — أدوار موروثة من فريق المشروع
  - **Group** — أدوار موروثة من المجموعة

## 2. آليات التوارث بين المستويات التنظيمية

### 2.1 مسارات التوارث الرسمية

```
                    ┌──────────────┐
                    │    System    │
                    │  (Global)    │
                    └──────┬───────┘
                           │ الأدوار العامة تسري على كامل النظام
                           ▼
                    ┌──────────────┐
                    │ Organization │
                    └──────┬───────┘
                           │ الأدوار المؤسسية تنتشر لكل المشاريع التابعة
                           ▼
                    ┌──────────────┐
                    │   Project    │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
      ┌──────────┐  ┌───────────┐  ┌────────┐
      │  Team    │  │   Group   │  │  User  │
      │(per-proj)│  │(cross-proj│  │(direct)│
      └────┬─────┘  └─────┬─────┘  └────────┘
           │               │
           └───────┬───────┘
                   ▼
           ┌──────────────┐
           │  User الفعلي │
           │  (مجموع كل   │
           │   المسارات)  │
           └──────────────┘
```

### 2.2 قواعد التوارث الرسمية

| القاعدة | الوصف |
| --------- | ------- |
| **التوارث من المؤسسة للمشروع** | إسناد دور على مستوى المؤسسة يمنحه تلقائياً لكل المشاريع المنتمية لها |
| **التوارث من المجموعة للمستخدم** | أعضاء المجموعة يرثون كل أدوار المجموعة في كل المشاريع المُسندة لها |
| **التوارث من الفريق للمستخدم** | أعضاء فريق المشروع يرثون أدوار الفريق في ذلك المشروع |
| **التراكم (Accumulation)** | المستخدم يحصل على **اتحاد (Union)** كل الصلاحيات من جميع مسارات التوارث |
| **لا يوجد رفض صريح (No Explicit Deny)** | لا توجد آلية لحرمان مستخدم من صلاحية تم منحها عبر مسار آخر |

### 2.3 ترشيح النطاق عند الإسناد (Scope Filtering)

هذا المفهوم هو **نقطة التلاقي** بين المستويات التنظيمية والنطاقات:

> **القاعدة الرسمية الحرجة:** عند إسناد دور في مستوى تنظيمي معين، YouTrack يُفعِّل فقط الصلاحيات التي يتوافق نطاقها مع ذلك المستوى.

**مثال توضيحي:**

```
الدور: "Custom Manager"
  ├── صلاحية: Create User        (نطاق: Global)
  ├── صلاحية: Create Project     (نطاق: Global)
  ├── صلاحية: Read Issue         (نطاق: Project)
  └── صلاحية: Update Issue       (نطاق: Project)

إسناد هذا الدور على مستوى المشروع:
  ✅ Read Issue       → مُفعَّلة (نطاق Project يتوافق مع مستوى المشروع)
  ✅ Update Issue     → مُفعَّلة (نطاق Project يتوافق مع مستوى المشروع)
  ❌ Create User      → مُتجاهلة (نطاق Global لا يتوافق مع مستوى المشروع)
  ❌ Create Project   → مُتجاهلة (نطاق Global لا يتوافق مع مستوى المشروع)
```

## 3. الأدوار الافتراضية وعلاقتها بالمستويات التنظيمية

### 3.1 الأدوار المُعرَّفة مسبقاً (Predefined Roles)

| الدور | المستوى التنظيمي المعتاد | النطاقات المُغطاة | الوصف |
| ------- | -------------------------- | ------------------- | ------- |
| **System Admin** | System | Global + Organization + Project | وصول كامل لكل شيء في النظام |
| **Project Admin** | Project | Project | إدارة إعدادات المشروع + كل صلاحيات Contributor |
| **Contributor** | Project | Project | إنشاء وتعديل التذاكر والتعليقات |
| **Observer** | Project | Project | وصول للقراءة فقط (Read-Only) |
| **Project Creator** | System | Global | إنشاء مشاريع جديدة فقط |
| **User Manager** | System | Global | إنشاء وإدارة حسابات المستخدمين فقط |

### 3.2 ملاحظات رسمية مهمة على الأدوار الافتراضية

- الأدوار الافتراضية **للقراءة فقط (Read-Only)** — لا يمكن تعديلها مباشرة.
- لتخصيص دور افتراضي: يجب **نسخه (Clone)** أولاً، ثم تعديل النسخة.
- المسار: `Administration > Access Management > Roles > [الدور] > Clone`.

## 4. الصلاحيات الضمنية (Implied Permissions)

### 4.1 المفهوم الرسمي

عند إضافة صلاحية إلى دور، قد يُضيف YouTrack تلقائياً صلاحيات أساسية مطلوبة لعمل الصلاحية الأصلية:

| الصلاحية الأصلية | الصلاحية الضمنية المُضافة تلقائياً | السبب |
| ------------------ | ------------------------------------ | ------- |
| Create Issue | Read Project Basic | لا يمكن إنشاء تذكرة بدون الوصول الأساسي للمشروع |
| Read Issue | Read Project Basic | لا يمكن قراءة تذكرة بدون الوصول الأساسي للمشروع |
| Delete User | Read User Details | لا يمكن حذف مستخدم بدون القدرة على قراءة بياناته |

### 4.2 الصلاحيات الملازمة (Inherent Permissions)

مفهوم مختلف عن الصلاحيات الضمنية:

> **القاعدة الرسمية:** عندما يملك المستخدم صلاحية إنشاء كيان ما، يحصل تلقائياً على صلاحية **قراءة المحتوى الذي أنشأه هو** — بدون الحاجة لصلاحية قراءة مستقلة.

**مثال:** مستخدم يملك صلاحية `Create Issue` → يمكنه قراءة التذاكر التي أنشأها هو، حتى لو لم يملك صلاحية `Read Issue` الصريحة.

## 5. طرق إسناد الأدوار على المستويات التنظيمية المختلفة

### 5.1 الإسناد على مستوى النظام (Global Assignment)

```
المسار: Administration > Access Management > Roles
الإجراء: تعيين دور عام لمستخدم أو مجموعة
النتيجة: الصلاحيات العامة تسري على كامل النظام
```

### 5.2 الإسناد على مستوى المؤسسة (Organization Assignment)

```
المسار: Administration > Access Management > Organizations > [المؤسسة] > Access Tab
الإجراء: تعيين دور لمستخدم أو مجموعة على مستوى المؤسسة
النتيجة: الصلاحيات تسري على كل مشاريع المؤسسة
```

### 5.3 الإسناد على مستوى المشروع (Project Assignment)

```
المسار: Project Settings > People
الإجراء: إضافة مستخدم أو مجموعة وتعيين دور
النتيجة: الصلاحيات تسري على المشروع المحدد فقط
```

### 5.4 الإسناد المباشر للمستخدم (Direct User Assignment)

```
المسار: Administration > Users > [المستخدم] > Roles Tab > Assign Role
الإجراء: اختيار الدور + تحديد المشاريع المستهدفة
النتيجة: الصلاحيات تسري حسب المشاريع المحددة
```

## 6. ملخص: الفرق بين المستويات التنظيمية والنطاقات

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                                                                             │
│   المستويات التنظيمية                 النطاقات (Scopes)                      │
│   (Organizational Levels)                                                   │
│                                                                             │
│   ┌─────────────────────┐            ┌─────────────────────┐                │
│   │ تُحدد الهيكل الإداري │            │ تُحدد خاصية الصلاحية │                │
│   │ وآليات الإسناد       │            │ ونطاق تأثيرها       │                │
│   └─────────────────────┘            └─────────────────────┘                │
│                                                                             │
│   مَن يملك الدور؟                    أين تسري الصلاحية؟                     │
│   كيف يتوارث؟                        هل تتوافق مع مستوى الإسناد؟            │

│                                                                             │
│   أمثلة:                             أمثلة:                                │
│   - System, Organization             - ScopeGlobal                          │
│   - Project, Team                    - ScopeOrganization                    │
│   - Group, User                      - ScopeProject                         │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
```
