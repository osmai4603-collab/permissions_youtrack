# بحث: أنواع المجموعات في YouTrack والفروقات بينها

> **المصدر الرسمي**: توثيق JetBrains YouTrack Server 2026.2
> **تاريخ البحث**: 2026-10-05
> **آخر تحديث للتوثيق الرسمي**: 29 September 2026

---

## 1. الخلاصة التنفيذية

في YouTrack توجد **ثلاثة أنواع مختلفة جوهرياً** من المجموعات، وهي **ليست شيئاً واحداً**:

| الخاصية | User Groups | Project Teams | Customer Groups |
| --- | --- | --- | --- |
| **الغرض الأساسي** | إدارة الصلاحيات والوصول عبر مشاريع متعددة | إدارة تعيين الأدوار داخل مشروع **واحد** | مشاركة تذاكر الدعم الفني مع جماهير خارجية |
| **النطاق (Scope)** | عالمي (Global) - يمكن استخدامه عبر كامل النظام | خاص بالمشروع (Project-specific) | خاص بمشاريع Helpdesk |
| **يمكن تعيين أدوار له؟** | ✅ نعم | ✅ نعم (ضمن المشروع فقط) | ❌ لا |
| **يمكن تداخله (Nesting)؟** | ✅ نعم | ❌ لا | ❌ لا |
| **يمكن إضافته لفريق مشروع؟** | ✅ نعم | — (هو فريق المشروع) | ❌ لا |
| **الحالة الافتراضية** | يُنشأ يدوياً أو تلقائياً | يُنشأ تلقائياً مع كل مشروع | يُنشأ يدوياً |

## 2. User Groups (مجموعات المستخدمين)

### 2.1 التعريف الرسمي
>
> "A group is a collection of user accounts. Groups let you manage multiple accounts more efficiently. You can grant and restrict access to specific features in YouTrack for all group members at once."

المجموعة هي **مجموعة من حسابات المستخدمين** تُستخدم لإدارة الحسابات بكفاءة أكبر. يمكن منح أو تقييد الوصول لميزات معينة لجميع أعضاء المجموعة دفعة واحدة.

### 2.2 متى تُستخدم؟

- عندما تريد إدارة **نفس مجموعة المستخدمين عبر مشاريع متعددة**
- يمكن تعيين أدوار مختلفة للمجموعة في مشاريع مختلفة
- يمكن إضافة المجموعة إلى فرق المشاريع
- تحديث عضوية المجموعة يُحدّث الوصول لأعضائها **أينما استُخدمت المجموعة**

### 2.3 المجموعات الافتراضية (Default Groups)

يوجد مجموعتان افتراضيتان في YouTrack:

| الاسم | Auto-join | الدور الافتراضي | الملاحظات |
| --- | --- | --- | --- |
| **All Users** | مُفعّل (لا يمكن تعطيله) | لا يوجد | جميع الحسابات تُضاف تلقائياً - بما فيها حساب الضيف |
| **Registered Users** | مُفعّل (لا يمكن تعطيله) | Observer (عالمياً) | جميع الحسابات ما عدا حساب الضيف |

**الفرق الجوهري بينهما**: حساب الضيف (Guest) مُستبعد من مجموعة `Registered Users` لكنه عضو في `All Users`.

### 2.4 العمليات المتاحة على المجموعات

1. **إنشاء مجموعة** (Create a Group)
2. **تداخل مجموعة تحت أخرى** (Nest a Group under Another Group)
   - المجموعة المتداخلة ترث جميع الأدوار من المجموعة الأم
3. **دمج المجموعات** (Merge Groups)
4. **دمج مجموعة في فريق مشروع** (Merge a Group into a Project Team)
5. **إضافة وإزالة الأعضاء** (Add and Remove Members)
6. **تعديل الإعدادات الأساسية** (Edit Basic Group Settings)
7. **إدارة صلاحيات المجموعة** (Manage Group Access)
8. **حذف المجموعة** (Delete Groups)

### 2.5 المجموعات والرؤية (Visibility)
>
> إنشاء مجموعة **لا يجعلها تلقائياً** متاحة كخيار في قائمة "Visible to" للقضايا والتعليقات والمرفقات. يجب أن تكون عضواً في المجموعة لاختيارها في إعدادات الرؤية.

## 3. Project Teams (فرق المشاريع)

### 3.1 التعريف الرسمي
>
> "Use a project team when users need the same role in a single project. Each project has one project team, and its role assignments apply only to that project."

### 3.2 الخصائص الجوهرية

- **لكل مشروع فريق واحد فقط** (1:1 relationship)
- تعيينات الأدوار تنطبق **فقط على ذلك المشروع**
- يمكن إضافة **أفراد أو مجموعات مستخدمين** إلى فريق المشروع
- يُعرض في صفحة Groups مع لاحقة `-team` مُلحقة باسم المشروع

### 3.3 الفرق بين Project Team و User Group

| User Group | Project Team |
| --- | --- |
| يُعرّف **من هو** المستخدم عالمياً | يُعرّف **ما هو دوره** في سياق مشروع محدد |
| يمكن استخدامه عبر مشاريع متعددة | مقيّد بمشروع واحد |
| يُنشأ يدوياً | يُنشأ تلقائياً مع المشروع |

### 3.4 العمليات المتاحة

- عرض معلومات الفريق في الشريط الجانبي (Details sidebar)
- النقر على اسم الفريق يفتح صفحة **People** في إعدادات المشروع
- إضافة/إزالة أعضاء من فريق المشروع

### 3.5 العرض المختلط (Groups and Teams)

عند تفعيل فلاتر Groups و Teams معاً، يظهر عرض مختلط يساعد في:

- تحديد المجموعات التي تُكرر عضويات وتعيينات أدوار فريق المشروع
- دمج المجموعات المتكررة في فريق المشروع بأمان

## 4. Customer Groups (مجموعات العملاء)

### 4.1 التعريف الرسمي
>
> "Customer groups let you organize helpdesk reporters by company, department, team, or any other external audience. When a helpdesk ticket is shared with a customer group, members of the group can view the ticket and add public comments."

### 4.2 الخصائص الجوهرية

- مبنية على نموذج المجموعة القياسي لكن **محصورة في حالات Helpdesk**
- تُميّز بعلامة **Helpdesk** في قائمة المجموعات
- يمكن أن تشمل: reporters، standard users، و agents

### 4.3 القيود الجوهرية ⚠️

> **Customer groups don't grant roles or permissions. They only provide helpdesk ticket access when the group is used in helpdesk-specific settings.**

| القيد | التفصيل |
| --- | --- |
| **لا أدوار** | لا يمكن تعيين أدوار لمجموعات العملاء |
| **نوع ثابت** | لا يمكن تحويل مجموعة مستخدمين عادية إلى مجموعة عملاء والعكس |
| **لا تداخل** | لا يمكن تداخلها تحت مجموعات أخرى ولا تحتوي مجموعات فرعية |
| **لا فرق مشاريع** | لا يمكن إضافتها لفرق المشاريع |
| **لا حقول مخصصة** | لا يمكن استخدامها كقيم في حقول المجموعة المخصصة |
| **لا رؤية عامة** | لا يمكن استخدامها في إعدادات الرؤية للمقالات أو التعليقات أو المرفقات أو لوحات Agile أو التقارير أو لوحات التحكم أو القضايا العادية |
| **لا مزامنة خارجية** | المجموعات المُزامنة من موفر هوية خارجي غير مدعومة كمجموعات عملاء |

### 4.4 آلية عمل Customer Groups في Helpdesk

#### مجموعات العملاء على مستوى المشروع

- كل مشروع helpdesk لديه صفحة **Customer Groups** في إعدادات المشروع
- المجموعات المضافة تشكّل **كتالوج** مجموعات العملاء المتاحة لمشاركة التذاكر

#### المشاركة التلقائية (Auto-share)

- يمكن تفعيل **Auto-share** لمجموعة عملاء
- عند التفعيل: التذاكر الجديدة من أعضاء المجموعة تُشارك تلقائياً مع المجموعة
- عند التعطيل: الوكلاء يمكنهم المشاركة اليدوية

#### مشاركة التذاكر (Ticket Sharing)

- الوكلاء يمكنهم مشاركة تذكرة مع أي مجموعة عملاء في كتالوج المشروع
- أعضاء المجموعات المختارة يمكنهم **عرض التذكرة وإضافة تعليقات عامة**
- إذا أُزيل مُبلّغ من مجموعة عملاء، تُزال المجموعة من التذاكر التي يكون فيها هذا المستخدم هو المُبلّغ

### 4.5 التبويبات في إعدادات مجموعة العملاء

| التبويب | الوصف |
| --- | --- |
| **Members** | عرض المستخدمين في المجموعة - إضافة/إزالة أعضاء |
| **Projects** | عرض مشاريع Helpdesk التي تستخدم هذه المجموعة |
| **Settings** | إعدادات Auto-share الخاصة بالمشروع + إعدادات عالمية (auto-join, 2FA) |

## 5. إدارة أدوار المجموعات (Group Role Management)

### 5.1 عرض صلاحيات الوصول لمجموعة

**المسار**: `Administration > Access Management > Groups` → اختر مجموعة → تبويب **Roles**

**الصلاحيات المطلوبة للعرض**:

| النطاق | الصلاحية المطلوبة |
| --- | --- |
| عالمي (Global) | `Low-level Admin Read` |
| منظمة (Organization) | `Read Organization` + `Read Project Full` أو `Update Organization` |
| مشروع (Project) | `Read Project Full` |

### 5.2 منح دور لمجموعة (Grant a Role)

**الخطوات**:

1. `Administration > Access Management > Groups`
2. اختر المجموعة المراد تعيين دور لها
3. افتح تبويب **Roles** في الشريط الجانبي
4. انقر **Assign role**
5. اختر الدور من مربع حوار **Assign Role**
6. حدد مشروعاً أو منظمة أو **Global** (لجميع المشاريع)
7. انقر **Assign role** للتأكيد

**الصلاحيات المطلوبة للمنح**:

| النطاق | الصلاحية المطلوبة |
| --- | --- |
| عالمي (Global) | `Low-level Admin Write` |
| منظمة (Organization) | `Update Organization` |
| مشروع (Project) | `Update Project` |

### 5.3 سحب دور من مجموعة (Revoke a Role)

**الخطوات**:

1. `Administration > Access Management > Groups`
2. ابحث عن المجموعة واخترها
3. افتح تبويب **Roles**
4. حدد موقع تعيين الدور المراد إزالته
5. حدد تعيين الدور
6. انقر **Revoke role**
7. أكد الإجراء في مربع الحوار

**النتيجة**: يُسحب الدور من المجموعة ويفقد أعضاؤها الصلاحيات المرتبطة بالدور في المشروع.

**الصلاحيات المطلوبة للسحب**: نفس صلاحيات المنح.

### 5.4 ملاحظة مهمة حول الأدوار ذات النطاقات المختلطة

> YouTrack يفصل **تعريف الدور** عن **تعيين الدور**. يمكنك إنشاء أدوار بنطاقات مختلطة، لكن النظام يُفعّل فقط الصلاحيات المتوافقة مع المستوى المُعيّن فيه.

| مستوى التعيين | السلوك |
| --- | --- |
| **عالمي** | جميع الصلاحيات تُعتبر صالحة |
| **منظمة** | الصلاحيات ذات النطاق العالمي تُتجاهل |
| **مشروع** | الصلاحيات ذات النطاق العالمي والتنظيمي تُتجاهل. YouTrack يمنع التعيين إذا لم يحتوِ الدور على صلاحية واحدة على الأقل بنطاق المشروع |

## 6. صلاحيات إدارة المجموعات ذاتها

### 6.1 من يمكنه عرض المجموعات؟

- مستخدمون لديهم صلاحية `Update Project` أو `Low-level Admin Read`
- يمكن منح وصول إضافي عبر الميزة الاختيارية **Read Groups**

### 6.2 من يمكنه تعديل المجموعات؟

- يمكن منح الوصول عبر الميزة الاختيارية **Update Groups**

### 6.3 قاعدة إضافة الأعضاء
>
> **لإضافة مستخدمين أو مجموعات فرعية إلى مجموعة، يجب أن تمتلك مسبقاً كل صلاحية ممنوحة للمجموعة المستهدفة.**
>
> هذا القيد **لا ينطبق** عند إزالة الأعضاء أو على المستخدمين الذين يملكون صلاحية `Low-level Admin Write`.

## 7. الكينونات (Entities) المتعلقة بالمجموعات

### 7.1 خريطة الكينونات

```
┌─────────────────────────────────────────────────┐
│                  YouTrack Instance               │
│                                                  │
│  ┌─────────────┐    ┌─────────────────────────┐  │
│  │ User Account│───▶│ Group (User Group)       │  │
│  │             │    │  ├─ Name                 │  │
│  │  - username │    │  ├─ Description          │  │
│  │  - email    │    │  ├─ Auto-join (bool)     │  │
│  │  - type     │    │  ├─ Members (users)      │  │
│  └─────────────┘    │  ├─ Subgroups (nested)   │  │
│                     │  ├─ Parent Group         │  │
│                     │  ├─ Role Assignments[]   │  │
│                     │  │   ├─ Role             │  │
│                     │  │   └─ Scope (project/  │  │
│                     │  │       org/global)     │  │
│                     │  └─ Viewable by /        │  │
│                     │     Updatable by          │  │
│                     └─────────────────────────┘  │
│                                                  │
│  ┌─────────────────────────────────────────────┐  │
│  │ Project                                     │  │
│  │  ├─ Project Team (1:1)                      │  │
│  │  │   ├─ Members (users + groups)            │  │
│  │  │   └─ Role Assignments (project-scoped)   │  │
│  │  ├─ Customer Groups[] (helpdesk only)       │  │
│  │  │   ├─ Auto-share (per project setting)    │  │
│  │  │   └─ Members (reporters/users/agents)    │  │
│  │  └─ Visibility Settings                     │  │
│  └─────────────────────────────────────────────┘  │
│                                                  │
│  ┌─────────────────────────────────────────────┐  │
│  │ Role                                         │  │
│  │  ├─ Name                                     │  │
│  │  ├─ Permissions[]                             │  │
│  │  │   └─ Permission                            │  │
│  │  │       ├─ Name                              │  │
│  │  │       └─ Scope (global/org/project)        │  │
│  │  └─ Assignable at (global/org/project)        │  │
│  └─────────────────────────────────────────────┘  │
│                                                  │
│  ┌─────────────────────────────────────────────┐  │
│  │ Organization                                 │  │
│  │  ├─ Name                                     │  │
│  │  ├─ Projects[]                                │  │
│  │  └─ Role Assignments (org-scoped)             │  │
│  └─────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────┘
```

### 7.2 الكينونات الرئيسية

| الكينونة | الوصف | العلاقات |
| --- | --- | --- |
| **User Account** | حساب المستخدم | ينتمي لمجموعات، عضو في فرق مشاريع |
| **User Group** | مجموعة مستخدمين | تحتوي أعضاء، قد تتداخل، تملك تعيينات أدوار |
| **Project Team** | فريق المشروع | 1:1 مع المشروع، يحتوي أعضاء ومجموعات |
| **Customer Group** | مجموعة عملاء | خاصة بـ Helpdesk، لا أدوار، تشارك التذاكر |
| **Role** | الدور | حاوية مسماة للصلاحيات |
| **Permission** | الصلاحية | حق وصول فردي، لها نطاق محدد |
| **Role Assignment** | تعيين الدور | يربط (دور + مجموعة/مستخدم + نطاق) |
| **Organization** | المنظمة | تجميع هرمي للمشاريع لتوحيد الأدوار |
| **Project** | المشروع | حاوية القضايا والتذاكر |

### 7.3 أنواع المستخدمين المرتبطة

| النوع | الوصف |
| --- | --- |
| **Standard User** | مستخدم عادي يمكنه العمل على القضايا |
| **Reporter** | حساب مُبلّغ (عادةً عميل خارجي في Helpdesk) |
| **Agent** | وكيل دعم فني يعمل على تذاكر Helpdesk |
| **Guest** | حساب ضيف - عضو في All Users لكن ليس Registered Users |

## 8. الأدوار الافتراضية المرتبطة

| الدور | الوصف |
| --- | --- |
| **System Admin** | إدارة كاملة للنظام |
| **Project Admin** | إدارة مشروع محدد |
| **Developer** | مطور يعمل على القضايا |
| **Reporter** | مُبلّغ عن القضايا |
| **Observer** | مراقب (القراءة فقط) - الدور الافتراضي لـ Registered Users |
| **Articles Editor** | محرر المقالات في قاعدة المعرفة |
